# 星途 TSP 全量复盘

> 复盘日期：2026-11
> 对象：`xingtu-tsp` 当前仓库
> 视角：业务需求、代码实现、国标/行标/地方标准、上线与合规风险
> 结论先行：**这是一个可运行、可演示、可二次开发的 TSP 参考实现，不是可直接备案/过检/上生产的合规成品。**

## 1. 复盘结论

| 维度 | 评价 | 说明 |
| --- | --- | --- |
| 业务闭环 | **B / 可用** | 车辆、终端、位置、行程、围栏、告警、指令、看板、用户、审计均有链路 |
| 工程质量 | **B / 可维护** | Rust 分层清晰，SQLx 三后端、测试与集群能力超出普通 Demo |
| 协议符合性 | **D / 子集** | JT/T 808-2019 仅 5 类消息 + 2 类应答；809/32960/1078/19056 未实现 |
| 安全 | **D / 演示级** | 默认密钥/默认账号/明文 TCP/CORS 全开/无多租户隔离 |
| 生产可用性 | **C- / 仍需整改** | 指令/离线/审计/迁移/Raft log+状态持久化已补；标准协议与完整租户实体仍缺 |
| 合规就绪度 | **D / 未就绪** | 无等保测评、无平台符合性检测、无监管平台接入 |

**一句话**：作为“TSP 教学/原型/POC 基线”是合格的；作为“道路运输车辆监控平台”上线，当前**不可以**。

## 4. 代码审计

### 4.1 做得好的部分

1. **单一写入入口**：HTTP、JT/T 808、模拟器统一走 `services::telemetry::ingest`，规则不会分叉。
2. **事务内一致性**：位置、状态、行程、围栏、告警在同一事务提交；避免“状态已变、告警丢失”。
3. **三后端适配**：`DbQuery` 对 `?N` 做 SQLite/PostgreSQL/MySQL 差异处理，MySQL 参数展开有测试。
4. **协议帧基础扎实**：7E 转义、XOR、BCD、长度校验、非法转义/校验失败拒绝，有单元测试。
5. **安全基线**：Argon2 密码、JWT、RBAC、审计；不是明文密码。
6. **集群意识**：幂等 seed、Redis 会话、事件总线、OpenRaft 控制面、K8s/HPA/PDB/NetworkPolicy。
7. **可观测性**：HTTP/WS/JT808/指令/告警计数、Prometheus 文本输出。

### 4.2 P0：上线前必须处理

#### P0-1 JT/T 808 注册即认证（本次已修复）

- 原实现：`src/jt808.rs` 收到 `0x0100` 后直接 `*authenticated = true`，并登记会话。
- 影响：任何能发注册帧的终端可绕过 `0x0102` 鉴权，直接上报位置。
- 本次修复：注册只返回 `0x8100` 鉴权码，不置为已认证；心跳也要求已鉴权；鉴权码改为随机 12 位后缀。
- 仍缺：鉴权码明文落库、失败重试/锁定、终端证书/mTLS。

#### P0-2 远程指令是随机模拟（已改）

- 已新增 `TSP_COMMAND_MODE=simulated|jt808|disabled`；生产禁止 simulated。
- `jt808` 模式已实现 `0x8300` 文本下行、`0x0001` 终端应答关联、15 秒超时；支持同节点与 Redis 跨网关副本路由。
- 仍需补 `0x8500` 车辆控制标准语义、重试/幂等/审计增强；当前 `0x8300` 是通用文本通道，不等同于完整车控协议。

#### P0-3 离线状态不会自动过期（已改）

- 已增加 leader-gated 离线巡检（每 60 秒，2 分钟无心跳/位置置离线），同时更新 `terminals.status` 与 `vehicle_state.status`。
- 尚未生成 `device_offline` 告警与 WebSocket 事件；看板会反映离线状态，但告警闭环仍缺。

#### P0-4 默认安全配置（已部分改）

- 已增加 `TSP_ENV=production` 启动校验：拒绝 demo、默认 JWT secret、默认 admin/admin123、模拟指令；空库必须提供 `TSP_ADMIN_PASSWORD`。
- CORS 默认同源，按 `TSP_CORS_ORIGINS` 白名单；WebSocket 改用 `Sec-WebSocket-Protocol: bearer.<JWT>`；登录失败 5 次/15 分钟限流。
- 仍需：JT/T 808 TLS/mTLS、短时 WS 票据、密钥轮换、反向代理限流；808 仍为明文 TCP。

#### P0-5 无多租户/组织数据域（已部分改）

- 已新增 `users.org_name` 迁移、JWT `org_name` claim、车辆列表/地图/详情/更新/轨迹/行程/指令/告警的组织域过滤；operator/viewer 只能访问本组织车辆。
- 已是“组织字符串”而非规范化 tenant 表；车辆、告警、指令、行程、dashboard、geofence 均已按组织过滤（空组织为平台级全局围栏）；租户配额/RBAC 细化仍需继续。

#### P0-6 标准接口缺失

- JT/T 809-2019 与 GB/T 32960.3-2025 已补**传输帧骨架**（`src/standards/`），但没有业务消息体、握手、加密与真实平台联调；JT/T 1078-2016、GB/T 19056-2021 未实现。
- 不能以“已对标/有帧编解码”代替“已符合”；标准矩阵见 [STANDARDS.md](STANDARDS.md)，接入边界见 [INTEGRATIONS.md](INTEGRATIONS.md)。

#### P0-7 Raft 控制面不是生产级（已补持久化）

- 已用 `src/raft_log.rs` 持久化 log/vote/committed/purge，用 `src/raft_state.rs` 持久化状态机。
- K8s 身份改为 `TSP_NODE_ID` 派生；新增 StatefulSet + headless Service + PVC 示例。
- 已实测 kill Leader 后重新选主、带同一数据目录重启旧 Leader 可重新加入。
- 仍缺：快照文件持久化、动态成员变更、跨 AZ 网络验证。

#### P0-8 无版本化迁移（已起步）

- 已加入 `schema_migrations` 表、`0001_baseline` 与 `0002_users_org_scope` 幂等迁移；启动时自动应用。
- 仍缺少完整 SQLx migration 目录、回滚/expand-contract、三后端 CI 校验；后续表结构变更应继续登记版本。

### 4.3 P1：上线前应处理

| 编号 | 问题 | 证据/影响 | 建议 |
| --- | --- | --- | --- |

| P1-11 | MySQL 限制 | `VARCHAR` 有界、`ON DUPLICATE KEY` 命中任意唯一键、无 migration | 生产用 PG 或固定 MySQL 迁移/长度评估 |

## 5. 标准符合性

完整矩阵、版本核对、地方标准示例见 **[STANDARDS.md](STANDARDS.md)**。核心结论：

- **JT/T 808-2019**：仅注册/鉴权/心跳/0x0200/0x8001/0x8100 子集，**不能声明符合**。
- **JT/T 809-2019**：未实现，无法接入部/省/企业平台交换。
- **GB/T 35658-2017**：部分平台功能，未做符合性检测。
- **JT/T 794-2019 / GB/T 19056-2021**：终端/记录仪侧，平台需接入合规设备。
- **JT/T 1078-2016**：视频/主动安全未实现。
- **GB/T 32960.1–.4-2025**：新能源远程服务协议未实现。
- **等保/汽车数据/密码应用**：未定级、未测评、未做国密/TLS/数据分类。
- **地方标准**：上海 DB31/T 1409.1–.3-2023、DB31/T 1561-2025，安徽 DB34/T 2690/2691/2692-2016 等需按运营地适用；不能全国通用。

## 7. 建议整改路线

### 0–2 周（止血）

1. 生产启动强制校验：拒绝默认 JWT secret、默认 admin 密码、demo=true。
2. 指令模块加 `TSP_COMMAND_MODE=simulated|jt808`，生产默认拒绝模拟。
3. 离线巡检（90–180s）+ `device_offline` 告警。
4. 审计查询/导出 + 保留 180 天；轨迹清理改定时任务。
5. K8s 关闭 Raft 或改 StatefulSet；固定节点 ID 问题先禁用。
6. 补 808 鉴权/心跳/注册失败路径测试。

### 2–6 周（协议补强）

1. 0x0100 全字段、0x0704 批量、0x8103/0x8104/0x8105/0x8106/0x8107。
2. 0x8201/0x8202/0x8203/0x8204、0x8300/0x8500 下行 + 应答。
3. 分包重组、加密/证书方案；用 808 符合性测试工具回归。

## 9. 最终判断

**保留的价值**：领域模型、事务内规则、三数据库适配、JT/T 808 帧基础、集群与可观测性、零依赖前端，足以作为 TSP 产品的工程起点。

**不能接受的现状**：把“808 子集”当“808 合规”、把“Raft 持久化”当“已完成高可用验证”、把“能启动”当“可备案”；车控虽已真实下行，但仍未完整对齐 0x8500。

**建议对外表述**：

> 星途 TSP 是 Rust 实现的 TSP 参考实现，覆盖车辆/终端/位置/行程/围栏/告警/指令/集群的最小闭环；JT/T 808-2019 为子集实现，尚未完成 JT/T 809、GB/T 32960、JT/T 1078 及等保/平台符合性检测，不可直接用于监管备案或生产车控。

# 标准协议接入骨架

本文件对应 `src/standards/`，是 **JT/T 809-2019** 与 **GB/T 32960.3-2025** 的传输层/帧层接入边界。

> 重要：当前只实现传输帧编解码，**没有实现完整业务消息体、平台握手、加密/压缩、命令交互**，不能声明标准符合性。目的是让后续协议实现有稳定接口、单元测试和清晰的 TODO。

## 1. JT/T 809-2019

代码：[`src/standards/jt809.rs`](../src/standards/jt809.rs)

已实现：

- `0x5B` / `0x5D` 定界
- 长度、报文流水号、业务消息 ID、加密标志、压缩标志
- CRC32 校验
- 编码/解码 round-trip 与坏 CRC 拒绝测试

未实现：

- 上级平台登录/注销/心跳（登录 body 子集已实现，握手状态机未实现）
- 车辆动态信息、报警、驾驶员、区域等业务消息体
- 加密（RSA/国密）、压缩
- 主/从链路、平台间转发、断点续传
- 与 JT/T 809 测试工具的符合性回归

扩展点：

```rust
let frame = Jt809Frame {
    msg_id: 0x1001,
    msg_sn: 1,
    encrypt: 0,
    compress: 0,
    body: payload,
};
let wire = frame.encode();
```

下一阶段应把 `body` 按 809 业务消息表编码，并增加 `msg_id -> handler` 路由。

## 2. GB/T 32960.3-2025

代码：[`src/standards/gb32960.rs`](../src/standards/gb32960.rs)

已实现：

- `0x23 0x23` 起始符
- 命令字、应答标志、17 字节 VIN、加密标志、数据长度
- 登录/实时/登出/心跳命令常量
- 编码/解码 round-trip 与坏起始符拒绝测试

已实现（子集）：

- 0x01 实时数据单元前 20 字节：车辆状态、充电状态、运行模式、车速、累计里程、总电压/电流、SOC、DC-DC、挡位、绝缘电阻、加速/制动踏板

未实现：

- 0x01 后续驱动电机、燃料电池、发动机、车辆位置、报警、极值数据块
- 0x02 平台登录 body 子集已实现；0x03 登出、0x04 心跳、平台握手状态机未实现
- 0x05/0x06/0x07/0x08 补发/参数查询/终端控制等
- 加密、RSA/国密、平台间转发
- 32960.4 一致性测试

## 3. 与 TSP 领域模型的关系

标准消息体最终应映射为：

```text
GB/T 32960 实时数据 ─┐
JT/T 808 0x0200    ─┼─▶ LocationSample / VehicleState / Alert
厂商自定义 MQTT    ─┘
```

当前 `LocationSample` 是接入层统一模型；建议不要在 codec 层直接写库，保持“解码 → 规范化事件 → ingest”的分层。

## 4. 验收边界

| 能力 | 当前 |
| --- | --- |
| 帧定界/长度/CRC | JT/T 809 已实现 |
| VIN/命令字/长度 | GB/T 32960 已实现 |
| 业务消息体 | 未实现 |
| 加密/压缩 | 未实现 |
| 平台握手/登录 | 未实现 |
| 监管平台联调 | 未实现 |
| 标准符合性检测 | 未进行 |

在完成业务消息体和真实平台联调前，对外只能表述为“标准协议接入骨架”，不能表述为“已支持 JT/T 809/GB/T 32960”。

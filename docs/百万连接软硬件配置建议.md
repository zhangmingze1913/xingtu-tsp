# 百万连接软硬件配置建议

> 适用项目：`xingtu-tsp`（JT/T 808 终端接入 + 定位/告警业务）
> 目标规模：**100 万终端长连接**
> 文档版本：2026-11-28 · 基于当前 `main` 分支代码（`f90beca` 之后）
> 相关文档：[CAPACITY.md](CAPACITY.md)、[PERFORMANCE.md](PERFORMANCE.md)、[CLUSTER.md](CLUSTER.md)、[TIMESERIES_BACKENDS.md](TIMESERIES_BACKENDS.md)、[OPERATIONS_GUIDE.md](OPERATIONS_GUIDE.md)

---

## 0. 结论摘要

| 维度 | 结论 |
|---|---|
| 单机能否扛 100 万？ | **不能**。单节点安全值约 **17 万连接**，需要 **6 台网关**（含 N+1 余量） |
| 真正的瓶颈 | **数据库写入（约 3.6 万行/秒）** > 连接内存 > CPU > 带宽 |
| 带宽 | 总入口仅约 **24 Mbps**，10GbE 绰绰有余 |
| CPU | 协议解析约 **0.1–0.2 核**，不是瓶颈 |
| 内存 | 100 万连接约 **20–24 GB**（内核 + 应用） |
| 关键前提 | 终端会话按 `terminal_id` 哈希分片；定位数据批量落库；心跳写节流 |

## 1. 业务模型与容量假设

### 1.1 终端消息模型

| 消息 | 频率 | 消息数/秒 | 平均字节 |
|---|---|---|---|
| `0x0200` 定位上报 | 30 s/次 | **33,333** | ~80 B |
| `0x0002` 心跳 | 60 s/次 | **16,667** | ~20 B |
| 注册 / 鉴权 | 每终端每小时约 1 次 | ~278 | ~40 B |
| `0x0704` 批量定位 | 5 min/次 × 10 点 | ~333（≈3,333 点/秒） | ~600 B |
| **合计** | | **≈ 50,000 msg/s** | **≈ 3 MB/s（24 Mbps）** |

> 以上为默认假设。实际部署请按终端的 `T1`（定位间隔）、`T2`（心跳间隔）替换后重算，公式见第 2 节。

### 1.2 资源推导

| 资源 | 计算 | 结果 |
|---|---|---|
| 连接内存（内核） | 1M × 12–20 KB | 12–20 GB |
| 连接内存（应用） | 1M × 4–8 KB | 4–8 GB |
| 文件描述符 | 1M + 30% 余量 | ≥ 1,300,000 |
| 协议解析 CPU | 50k × 2–5 µs | 0.1–0.25 核 |
| 定位写入 | 33.3k 行/秒（批量 500/事务） | 约 67 事务/秒 |
| 网络带宽 | 3 MB/s × 8 | ≈ 24 Mbps |
| 会话注册表 | 1M × ~200 B | ≈ 200 MB |

**瓶颈排序：数据库写入 > 连接内存 > 重连风暴 > CPU > 带宽。**

## 2. 容量计算公式

```text
消息率(msg/s)   = 终端数 × (1/T1 + 1/T2 + 注册频率)
带宽(bps)       = Σ 消息率 × 平均消息字节 × 8
连接内存(GB)    = 终端数 × 单连接内存(KB) / 1024 / 1024
网关节点数      = ceil(终端数 / 单节点安全连接数) + 1   # +1 为 N+1
DB 写入(行/s)   = 定位消息率 + 批量定位点数/s
DB 分片数       = ceil(DB写入 / 单片安全写入)
```

### 2.1 100 万终端测算表

| 项目 | 数值 | 说明 |
|---|---|---|
| 消息率 | 50,000 msg/s | T1=30s，T2=60s |
| 带宽 | 24 Mbps | 10GbE ×2 冗余即可 |
| 连接内存 | 20–24 GB | 内核 12–20 GB + 应用 4–8 GB |
| 网关节点 | **6 台**（每台 17 万连接） | 1.02M 连接，含 1 台冗余 |
| 写入行数 | 36,600 行/s | 定位 33.3k + 批量 3.3k |
| DB 分片 | **4–8 片** | 单片 5–9k 行/s |
| 会话表 | 200 MB | Redis / OpenRaft |

## 3. 硬件配置建议

### 3.1 JT808 网关节点（每台 17 万连接）

| 部件 | 配置 | 说明 |
|---|---|---|
| CPU | **16 核**（≥ 3.0 GHz） | 解析仅需 <0.1 核，余量给 TLS 握手与突发 |
| 内存 | **32 GB** | 17 万 × 24 KB ≈ 4 GB；其余给页缓存/突发 |
| 网卡 | **2×10GbE**（RSS 队列 ≥ 核数） | 每节点仅 ~4 Mbps，10GbE 为可靠性冗余 |
| 磁盘 | 系统盘 100 GB SSD | 数据面不落盘 |
| 数量 | **6 台**（N+1） | 5 台承载 + 1 台冗余 |

> 若开启 TLS，建议在四层负载均衡（LVS/NLB）终结 TLS，或使用会话票据（session ticket）降低重连握手成本。

### 3.2 写入 / 业务节点

| 部件 | 配置 |
|---|---|
| CPU | 8 核 |
| 内存 | 16 GB |
| 数量 | 4 台（可按写入吞吐水平扩展） |

### 3.3 数据库 / 时序库

| 方案 | 规格 | 适用 |
|---|---|---|
| PostgreSQL 16 + PostGIS | 32 核 / 128 GB / NVMe，4–8 分片 | 需要空间查询/复杂业务 |
| **TDengine / tsink**（`TSP_TIMESERIES_BACKEND`） | 16 核 / 64 GB / NVMe | 纯高吞吐时序写入（推荐 36k 行/s 场景） |
| Kingbase KGIS | 同 PG 规格 | 信创要求（见 `KINGBASE_KGIS.md`） |

**要点：**
- `telemetry` 表按月分区，历史数据冷热分离
- 批量写入：**每 100–500 行一个事务**（`ingest_locations` 已支持）
- 唯一性：使用 `telemetry_claims` 表的 `ON CONFLICT DO NOTHING`，避免「先查后插」的额外往返

### 3.4 会话注册表 / Raft

| 组件 | 规格 |
|---|---|
| Redis | 3 主 3 从，16 GB/节点（`TSP_REDIS_URL`） |
| OpenRaft | 3 或 5 节点（`TSP_RAFT_ENABLED` / `TSP_RAFT_PEERS`） |

### 3.5 负载均衡与网络

- 四层负载均衡（LVS-DR / 云 NLB / DPVS），按源 IP 或终端 ID 哈希做**粘性路由**
- 网关前置防火墙：会话表 ≥ 150 万，NAT 端口池充足
- 内外网分离：终端接入走公网/VPN，写入服务走内网

### 3.6 整机清单（100 万终端）

| 角色 | 数量 | 规格 |
|---|---|---|
| JT808 网关 | 6 | 16C / 32G / 2×10GbE |
| 写入服务 | 4 | 8C / 16G / 10GbE |
| 数据库分片 | 4–8 | 32C / 128G / NVMe |
| Redis | 6（3 主 3 从） | 8C / 16G |
| OpenRaft | 3–5 | 4C / 8G |
| 负载均衡 | 2（主备） | 8C / 16G |

## 4. 操作系统与网络参数

### 4.1 文件描述符

```ini
# /etc/security/limits.conf
*  soft  nofile  1048576
*  hard  nofile  1048576
```

```ini
# /etc/sysctl.d/99-jt808.conf
fs.file-max = 2097152
fs.nr_open  = 2097152
```

> systemd 服务需额外设置 `LimitNOFILE=infinity`（`limits.conf` 对 systemd 服务不生效）。

### 4.2 TCP 参数（长连接场景）

```ini
net.core.somaxconn            = 65535
net.ipv4.tcp_max_syn_backlog  = 65535
net.core.netdev_max_backlog   = 262144
net.ipv4.tcp_tw_reuse         = 1
net.ipv4.tcp_fin_timeout      = 15
net.ipv4.tcp_keepalive_time   = 300     # 5 分钟探测，配合应用层心跳
net.ipv4.tcp_keepalive_intvl  = 30
net.ipv4.tcp_keepalive_probes = 3
net.ipv4.tcp_rmem             = 4096 87380 4194304
net.ipv4.tcp_wmem             = 4096 65536 4194304
net.ipv4.tcp_mem              = 786432 1048576 1572864
net.core.rmem_max             = 8388608
net.core.wmem_max             = 8388608
net.ipv4.tcp_slow_start_after_idle = 0
net.ipv4.tcp_mtu_probing      = 1
net.ipv4.tcp_syncookies       = 1        # 抗 SYN 洪泛
```

> **不要开启 `tcp_tw_recycle`**（NAT 环境会随机丢连接，新内核已移除）。
> 终端为长连接、单连接流量小，**不要**把 `tcp_rmem/wmem` 调得过大，否则百万连接会吃光内存。

### 4.3 网卡与中断

```bash
ethtool -L eth0 combined 16
systemctl stop irqbalance
# 每个 rx/tx 队列绑定到独立 CPU 核（按 /proc/interrupts 生成脚本）
cpupower frequency-set -g performance
```

单队列网卡（虚拟机）可用 RPS/RFS：

```bash
echo ffffffff > /sys/class/net/eth0/queues/rx-0/rps_cpus
echo 32768    > /sys/class/net/eth0/queues/rx-0/rps_flow_cnt
```

### 4.4 连接跟踪（有防火墙/NAT 时）

```ini
net.netfilter.nf_conntrack_max = 2097152
net.netfilter.nf_conntrack_tcp_timeout_established = 86400
```

## 6. 架构拓扑与分片

```text
 100 万终端
    │  TCP 长连接（按 terminal_id 哈希分片 + 粘性路由）
    ▼
┌────────────────────────────────────────────┐
│ 四层负载均衡（LVS-DR / NLB）                │
└────────────────────────────────────────────┘
    ▼            ▼            ▼
[网关 ×6]    [网关 ×6]    [网关 ×6]      每台 17 万连接
    │            │            │
    └──── 会话注册（Redis / OpenRaft）────┘
    │
    ▼  批量/异步
[写入服务 ×4] ──► [时序库/TDengine 或 PG 分片 ×4–8]
    │
    ▼
[告警 / 规则引擎 / 查询 API]
```

**分片与路由要点：**

1. **哈希分片**：`hash(terminal_id) % N` 决定网关节点；LB 按源 IP 或终端 ID 做一致性哈希
2. **会话注册**：`cluster.register_session(phone, peer)`（`src/cluster.rs:330`），重连时旧连接被新连接顶掉
3. **重连风暴**：
   - 服务端已有 `Semaphore` 连接限制（`src/jt808/gateway.rs:51`）
   - 终端侧应实现**指数退避 + 随机抖动**，避免 100 万终端同时重连
   - 网关 `backlog` 与 `somaxconn` 对齐（65535）
4. **TLS 终结**：优先在 LB 终结；若网关直连 TLS，启用 session ticket 并评估握手 CPU

### 7.1 已完成（`perf(jt808)` 系列提交）

| 优化 | 位置 | 效果 |
|---|---|---|

## 8. 压测方案

### 8.1 工具

| 目的 | 工具 |
|---|---|
| 终端行为模拟 | 扩展 `tests/jt808_terminal_sim.rs`，多进程启动（每进程 5 万终端） |
| 纯连接风暴 | `tcpkali -c 100000 -T 600s host:18080` |
| 数据库写入 | 复用 `scripts/capacity.sql` + 实际网关写入混合 |

> 单进程模拟器最多约 5 万连接（受 fd 与事件循环限制），100 万需 **20 个进程 / 4–8 台压测机**。

### 8.2 阶梯与验收

| 阶段 | 终端数 | 消息率 | 持续时间 | 验收标准 |
|---|---|---|---|---|
| 基线 | 100,000 | 5,000 msg/s | 10 min | 错误率 < 0.01%，P99 处理 < 50 ms |
| 爬坡 | 300,000 | 15,000 msg/s | 各 10 min | 连接成功率 ≥ 99.9% |
| 爬坡 | 600,000 | 30,000 msg/s | 各 10 min | DB 写入无积压 |
| **目标** | **1,000,000** | **50,000 msg/s** | 30 min | 断线率 < 0.1%/h，P99 < 100 ms，CPU < 60% |
| 稳定性 | 1,000,000 | 50,000 msg/s | 2 h | 内存无增长，P99 不漂移 |
| 风暴 | 1,000,000 同时重连 | 瞬时 33,000+/s | 5 min 内恢复 | 无 accept 溢出，鉴权成功 |

### 8.3 必采指标

| 层 | 指标 | 来源 |
|---|---|---|
| 接入 | `jt808_connections`、`jt808_rejected_connections` | `src/metrics.rs` |
| 协议 | `jt808_frames`、`jt808_frame_errors`、`jt808_auth_failures` | 同上 |
| 业务 | `telemetry_ingested`、`telemetry_duplicates`、`alerts_created` | 同上 |
| 下行 | `jt808_downlinks` | 同上 |
| 系统 | fd、CPU、RSS、TCP 重传 | `ss -s`、`pidstat`、`nstat` |
| 数据库 | 写入延迟、连接数、锁等待 | PG/TDengine 监控 |

### 8.4 故障注入

1. **断网重连**：模拟 10 万终端同时断网 30 s 后恢复，观察退避与 accept 队列
2. **慢终端**：1% 终端只发不回，验证写缓冲与超时清理
3. **重复/乱序包**：验证 claims 去重与批量排序（`ingest_locations` 已按 `ts` 排序）
4. **超大/分片包**：触发分片上限（16 个并发分片、256 KB 预算）与拒绝逻辑
5. **鉴权失败风暴**：验证 `jt808_auth_failures` 与限流

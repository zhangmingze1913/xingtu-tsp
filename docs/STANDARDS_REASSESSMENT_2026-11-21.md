# TSP 标准复核与实现路径（2026-11-21）

> 本文件是**代码侧复核**，依据仓库当前源码、测试与接口，不是第三方检测报告，也不构成标准符合性或认证结论。
>
> 判定口径：
> - **完成（代码侧）**：编解码、网关/业务处理、错误语义、自动化测试均存在；不代表真实设备/监管平台互通。
> - **部分**：有报文子集或字段骨架，缺必选字段、完整消息、会话/重连/加密/压缩或真实验收。
> - **未实现**：没有可用实现，只有常量或文档。
> - **外部**：必须依赖真实终端、监管平台、KMS/HSM 或评估机构。

## 2. 已完成的协议能力（代码侧）

### 2.1 JT/T 808-2019 核心子集

- 7E 转义、校验、BCD、帧头/帧尾
- 0x0100 注册（旧 37 字节 + 2019 候选布局）
- 0x0102 鉴权
- 0x0002 心跳
- 0x0200 位置（常见附加项语义 + 原始 TLV 保留）
- 0x0704 批量位置（事务内去重、时间排序、上限）
- 0x0201 位置查询应答
- 0x8001 通用应答
- 0x8100 注册应答
- 0x8103/0x8104/0x8106/0x8107 参数/属性
- 0x8105 终端控制
- 0x8202 临时跟踪、0x8203 告警确认、0x8204 链路检测
- 0x8300 文本下发
- 0x8500 车辆控制（lock/unlock/start/stop 等已按 0x8500 下发，非文本；action flag 仍为演示 profile）
- 单终端单会话、Redis 跨节点 kick、分片重组
- 管理员 `raw_808` 原始下行通道（msg_id + hex body，审计/管理员限定），用于字段已确认但尚未内置的消息

### 2.2 JT/T 809-2019 子集

- 0x5B/0x5D 传输帧、长度、流水号、消息 ID、CRC32
- 登录体（时间/流水号/用户/密码/加密规则）
- 业务信封 0x1200
- 定位/告警候选体
- 平台 ACK 0x9001
- TCP / TLS 连接、重试窗口、退避
- 登录响应与会话状态

### 2.3 GB/T 32960.3 子集

- `$$`（2025）/`##`（2016）传输头、BCC 校验、命令、应答、VIN、长度
- 0x0B 数据单元加密密钥交换（2025 表 31）
- 0x01 登录
- 0x02 实时数据（整车/位置/极值等）
- 0x03 补发数据
- 0x04 登出
- 0x05 平台登录、0x06 平台应答
- 0x07 心跳、0x08 时钟校正
- 电机、电池电压/温度、报警、位置、极值数据段
- 加密帧显式返回 `Encrypted`，不静默当明文处理

### 2.4 JT/T 1078-2016 媒体链路

- 30 字节媒体头、包编解码、序列/时间戳
- 帧重组、乱序缓冲、上限保护
- 实时/回放请求与控制、资源列表
- H.264 Annex-B 分割/重组、SPS/PPS/IDR
- AAC ADTS 头解析
- FFmpeg H.264→RGB24、AAC→PCM16
- fMP4 remux（MSE 可消费）
- UDP 监听 → MediaHub → 增量取帧 → chunked fMP4
- MSE 演示/实时页面、会话列表、停止清理
- 媒体接口 JWT + 写角色鉴权

## 4. 下一步完整实现路径

### Phase A：版本冻结与证据基线（1 周）

1. 逐项确认项目适用的标准版本（808/809/1078/1077/32960 及地方标准），形成版本台账。
2. 用官方全文/接口文档补全 `catalog` 的必选/可选字段、错误码、方向。
3. 建立报文样本库：正常、边界、非法、分片、重传、加密、乱序。
4. 修正文档与目录漂移（旧路线图仍把 1078 标为未实现，已在本复核修正）。

**DoD**：每个声明消息都有正/反用例；目录与代码一致；版本可追溯。

### Phase B：JT/T 808-2019 完整化（2–3 周）

按优先级：
1. 0x8301–0x8304、0x8400–0x8402、0x8600–0x8608。
2. 0x8700–0x8702、0x8800–0x8805。
3. 0x0100/0x0107 2019 全字段。
4. 0x0200 附加项全量语义。
5. 0x0704 分片/乱序/超时/限流。
6. 协议层加密/压缩、流水号回绕、全局限流。
7. 真实终端抓包回归。

**DoD**：项目必选消息 100%；异常/重传/并发测试；至少 2 家终端互通。

### Phase C：JT/T 809-2019 平台交换（2–3 周）

1. 完整消息目录与业务体。
2. 上下级平台握手、鉴权、平台编码映射。
3. 加密/压缩、CRC/长度/流水号校验。
4. 断线重连、重发、去重、顺序保持。
5. 省/部/市监管平台联调。

**DoD**：809 必选消息互通；断网/重连/重复包测试通过；监管平台报告。

### Phase D：GB/T 32960.3 完整化（2–3 周）

1. 0x01/0x02/0x03 完整数据单元（整车/电机/电池/报警/极值）。
2. 0x04–0x08 会话与平台交互。
3. 加密/解密、VIN/ICCID 校验、时间/序列。
4. 现行版本与地方监管差异适配。
5. GB/T 32960.4 一致性预演。

**DoD**：必选字段全覆盖；与 2 家新能源终端/平台互通；数据对账。

### Phase E：JT/T 1078/1077（3–4 周，外部依赖）

1. 真实终端信令与媒体接入。
2. 对讲、主动安全、录音等扩展。
3. JT/T 1077 平台功能/性能/可靠性逐条证据。
4. 弱网、乱序、长连接、低延迟调优。

**DoD**：项目范围条款逐项实现/测试/证据；真实终端联调报告。

### Phase F：行驶记录仪与地方标准（按项目）

1. GB/T 19056 数据读取/取证/校验。
2. 地方标准 adapter 独立目录，不污染 808 核心。
3. 按当地现行有效版本 + 接口文档 + 测试用例验收。

### Phase G：安全合规与认证（并行）

1. 等保 2.0 定级/备案/测评整改。
2. 汽车数据/个人信息：同意、最小必要、查询/更正/删除/导出、留存。
3. 密码应用：国密 TLS、密钥全生命周期、密评。
4. 第三方检测/认证。

## 5. 建议的下一步（代码侧）

在跳过真实环境的前提下，按以下顺序继续：

1. **808 剩余消息**：0x8301–0x8304、0x8400–0x8402、0x8600–0x8608。
